## 테스트 원칙
- 각 동작은 테스트를 먼저 작성하고 실패(RED)를 확인한 뒤 최소 구현한다.
- 기본 검증은 네트워크/계좌 없이 fixture로 실행한다.
- 어떠한 테스트도 주문 API를 호출하지 않는다.
- 키움 API 요청은 HTTP 세션/전송을 주입해 요청 URL, API ID, payload, 연속조회 헤더를 검증한다.

## 단위 테스트

### UT-01: 정상 일봉 요청
- Given: 테스트용 auth 및 HTTP 응답 fixture
- When: 지정 종목과 기준일로 일봉을 조회
- Then: 문서 조사로 확인한 API-ID 및 조회 contract에 맞춰 요청하고 OHLCV 행을 반환한다. live 호환성은 별도로 미검증이다.

### UT-02: 일봉 필드 정규화
- Given: 키움 응답의 날짜/가격/거래량 값이 문자열이며 가격 부호 규칙이 포함된 fixture
- When: 정규화 실행
- Then: 거래일 오름차순의 유효한 숫자형 OHLCV로 변환하고 잘못된 행은 명시적으로 거부/보고한다.

### UT-03: 연속 조회
- Given: 첫 응답이 continuation을 알리고 다음 페이지 fixture가 제공됨
- When: 목표 데이터 수까지 조회
- Then: 공식 규약에 따른 continuation 헤더/키로 다음 페이지를 요청하고 날짜 중복을 제거한다.

### UT-04: 데이터 수 부족 및 API 오류
- Given: 빈 응답, 오류 코드, HTTP 오류 또는 60거래일 미만 데이터
- When: 조회 또는 백테스트 실행
- Then: 해당 오류/데이터 부족을 명시하며 mock 결과나 성공 결과로 조용히 대체하지 않는다.

### UT-05: 최적화 결과의 입력 의존성과 결정성
- Given: 고정된 60일 OHLCV fixture
- When: 같은 전략/파라미터를 반복 평가
- Then: 결과가 동일하며, 입력 가격을 바꾸면 성과 지표가 실제 입력에 따라 달라진다. 난수 기반 지표는 제거하거나 seed/정의가 명시된다.

### UT-06: 주문 미호출 보장
- Given: 일봉 조회 및 최적화 실행
- When: T7 전체 분석 경로 실행
- Then: 주문/매수/매도 endpoint 호출 횟수는 0이다.

## 통합 테스트

### IT-01: fixture에서 60일 최적화까지
- Given: 네트워크 없이 주입된 60거래일의 OHLCV fixture
- When: optimizer의 실데이터 모드로 실행
- Then: fixture 데이터가 optimizer까지 전달되고 실제 가격열로 계산된 결과가 반환된다.

### IT-02: 모의 API 조회 실패의 fail-closed 동작
- Given: 조회 오류 또는 불완전 응답
- When: T7 실행
- Then: 최적화/추천 결과를 성공처럼 반환하지 않고 원인과 함께 실패한다.
