## 목표
T7 요구사항인 키움 REST API 일봉 조회를 기존 백테스트/최적화 경로에 안전하게 연결하고, 실제 주문 없이 데이터 및 계산 로직을 자동 테스트한다. 60일 백테스트가 mock_history 기반 결과 대신 주입된 일봉 데이터로 실행되도록 한다.

## 범위
- 일봉 조회 API를 테스트 가능한 의존성으로 구현한다.
- 데이터 응답을 일관된 날짜/OHLCV 형식으로 검증·정규화한다.
- 연속 조회, 데이터 부족, 빈 응답, HTTP/API 오류를 안전하게 처리한다.
- 기존 mock 경로를 명시적으로 보존하되 실제 데이터가 없는 경우 실데이터 결과인 것처럼 조용히 대체하지 않는다.
- 최적화 계산이 같은 입력 데이터에 대해 결정적이 되도록 한다.
- 테스트 fixture로 네트워크 없이 실행되는 검증을 제공한다.

## 제외 범위 및 안전 경계
- 매수·매도 주문, 실계좌/모의계좌 주문 실행, 실전 주문 활성화는 하지 않는다.
- 사용자 API 키·시크릿·계좌번호를 요청하거나 저장하지 않는다.
- 실서버 호출은 자동 테스트에 포함하지 않는다. 필요 시 조회 전용 연결도 별도 사용자 설정 및 수동 승인 대상으로 둔다.
- 수익 보장, 투자 추천의 실효성, 기존 백테스트 수치를 실전 성과로 주장하지 않는다.
- 커밋·푸시는 해당 단계의 테스트와 독립 리뷰가 통과한 뒤 사용자가 요청한 단위별 전달 흐름에 따라 수행한다. 실계좌 호출·실주문은 별도 승인 없이는 금지한다.

## 구현 전 확인사항
- 키움 공식 가이드에서 운영/모의 API 호스트 및 토큰 발급 정보를 확인했다. 일봉 차트의 경로, API ID, 요청/응답 필드, 연속조회 규약은 구현 전에 공식 명세를 다시 대조하고 근거를 결과 문서에 남긴다.
- 기존 `api/kiwoom_api.py`는 요청 간 throttle을 갖고 있지만 일봉 메서드는 없다.
- 기존 `api/strategy_optimizer.py`는 `mock_history`와 고정 수익률·무작위 보유일을 사용한다. 실데이터 주입 경계가 필요하다.
- `api/strategy_optimizer.py`가 이미 수정된 작업 트리에 있으므로 먼저 diff를 확인하고 해당 변경을 유지한 채 최소 패치한다.
- 현재 저장소의 paper 주문 코드에는 paper 잔고/수량 부족 시 실주문 요청으로 진행할 수 있는 경로가 관찰됐다. 이 결함은 거래 안전상 별도 차단/회귀 테스트가 필요하며, T7 범위를 넘어 임의 수정하지 말고 실주문 실행은 계속 금지한다.
